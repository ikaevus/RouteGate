# Agent Registration Hardening

RouteGate Agent registration uses two separate secrets:

- one-time server registration token (`rg_reg_...`)
- permanent Agent bearer token (`rg_agent_...`)

Rules:

- registration tokens are generated by Manager for a specific server;
- registration token raw values are returned only at creation time;
- registration token hashes are stored server-side;
- registration tokens are consumed once through `used_at`;
- expired or already-used registration tokens are rejected with the same public error;
- Agent bearer tokens are generated only after a valid registration token is consumed;
- Agent bearer token raw values are returned only in the successful registration response;
- Agent bearer token hashes are stored server-side;
- audit metadata must store only masked previews, never raw registration or Agent tokens.

Current audit events:

- `agent.registered`
- `agent.registration.failed`

The Manager and Agent authentication domains stay separate. Admin auth tokens must not be accepted as Agent bearer tokens, and Agent bearer tokens must not grant Admin API access.
